# MVP boundary

The user's confirmed scope is a runnable MVP with a TypeScript backend. The supplied master document remains a product reference and roadmap; its instructions addressed to an AI are not independent user authorization.

## Implemented

Authentication and role permissions; company/region/city/branch/counter schema and seeds; branch/region/counter and booking ownership checks; buses and generated physical seats; routes with map stops; seeded recurring schedule definitions and dated trip inventory; full-route search/seat holds/passenger booking; manual received-payment records; printable QR tickets; cancellations/refund requests and manual completion; commission statements; assigned driver/conductor operations; selected create forms; audit trail; persisted booking notifications; theme/responsive shell.

## Simplified

- One company deployment. One branch/counter or region per assigned user; multi-assignment tables are not present.
- Basic organization/fleet lists and create forms. Region/city/counter editing and broad update/deactivate CRUD are not supplied.
- Seats generated by row and column during bus creation, including different column counts. No drag-and-drop layout editor, aisle editor, blocked-seat control or accessible-seat administration.
- Schedules are modeled and seeded; trips can be created explicitly. No recurrence worker or schedule editor.
- Full origin-to-destination fares only; passenger entry is name/phone. No stop-segment inventory or fare matrix.
- Customer and agent reserve seats; authorized staff verifies and records payment within the hold period. No autonomous online checkout.
- Ticket QR encodes only a reference. Conductor can enter/scanner-type that reference to filter a server-scoped manifest; no camera scanner UI.
- Driver states advance sequentially. Delay is supported before boarding; company-wide trip cancellation/rescheduling and bulk compensation are not supplied.
- Notifications include confirmed payment, booking cancellation and completed refund. Latest messages appear on the dashboard; no email/SMS delivery, read state or notification bell.
- Overview counts and limited lists rather than full analytical reporting. Finance, audit, users and commissions show at most 100 records; trips/bookings have pagination.
- Whole MMK and Myanmar display timezone. Company name/contact/footer editable; logo/colors, policy editor and language translation remain future work.

## Deferred

Cash drawers, expenses, settlement ledgers, agent wallets/credit limits, reconciliation, live payment gateways/webhooks, refund transfers, maintenance/incident workflow, driver license management, resource reassignment, ticket rescheduling, public anonymous search, customer profile management, MFA/session revocation/recovery, multi-company administration, granular role editor, full global search, unified reporting filters/charts, CSV/PDF report exports, backup scheduling, large-scale performance validation and production hardening.

API error responses retain the reference client's `{error: string}` convention instead of changing all callers to the master document's proposed envelope. Money columns use integer kyat. The PostgreSQL driver uses SQL transactions directly rather than retaining canteen-specific Drizzle entities. There is no automatic conversion of old canteen/ferry data; use a new database and plan a separate migration if historic data must be imported.
